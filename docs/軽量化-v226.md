# v226：DB参照・保存処理の軽量化

2026-09-13。DBの内容・検索の順位・価格取得条件を維持して処理を削減。

## 変更

- 検索用の正規化済みカード名を初回利用時に作成し、ページ内で再利用する。検索語も全カードに対して毎回正規化しない。
- セット別索引を初回利用時に作成する。返却配列はコピーし、呼び出し元の変更で索引が壊れないようにする。
- Scryfallのカード情報更新では、レスポンスごとに現在の所持カードのID索引を作る。更新対象1件ごとの全件走査をなくす。通信待ち中の追加・削除も反映する。
- 保存対象を指定できるようにし、Wisdom Guild取得では価格キャッシュと取得状況、CardTrader取得では所持カード・価格キャッシュ・CardTrader情報だけを保存する。デッキやお気に入りの不要な再保存をなくす。
- HTMLのスクリプト参照バージョンがv216のままだったため、v226のService Worker事前キャッシュと一致させる。

## 検証

ローカルNode.jsで、v225の関数とv226の関数に同じ実DB（30,997件）を渡して比較。

- 日本語・英語・空文字・部分一致・完全一致など116ケース：結果と順位が一致。
- DBに含まれる全セット、空文字、存在しないセット：結果が一致。
- 保存対象の指定で他の保存領域を変更しないことを確認。
- 同一IDの複数所持ロット、通信中の追加・削除：更新結果が旧処理と一致。
- 検索合計：旧16,350ms、新889ms（新処理はキャッシュ作成後）。
- 新処理の初回「稲妻」検索：139ms。初回は名前キャッシュを作成する。

測定はPCのNode.js上で検索関数を比較したもので、画面全体や実機スマートフォンの時間ではない。名前キャッシュ分のメモリを使う。DB更新はページ再読み込み時に反映し、キャッシュも再作成する。

比較スクリプト・v225基準ファイル・測定JSONはローカルのexports/に保存。exports/はGit公開対象外。

## 今回の範囲外

起動時の価格取得ルール、Scryfall価格の採否、状態の対応表、DBのデータ削減、UIの統合は変更していない。アプリ更新ごとのDB再キャッシュを避ける設計は別途対応する。
