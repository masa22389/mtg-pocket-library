# 価格機能スリム化計画

2026-09-13 / v224のコードを確認した段階の実装案。未確定項目は下記の通り。

## 第1段階の範囲

- コレクションと個別カードの価格更新を共通の処理にする。
- Wisdom Guildを優先し、取得できなかったカードのみ設定済みのCardTraderで補完する。
- 手動価格を保持し、取得結果と表示に採用された価格を区別する。
- 更新結果に「更新・出品なし・通信失敗・未設定によるスキップ」を表示する。
- CardTraderのトークンなどは詳細設定にまとめる。
- 更新中の二重実行を防ぎ、終了・失敗時に操作可能な状態へ戻す。

## 利用方針の確認中

1. 起動時の価格自動取得を止めて手動更新を基本にするか。
2. 別状態の価格で代用せず、取得できない場合は前回価格を日時付きで残すか。
3. Scryfallを価格には使わないか、任意の参考価格として残すか。

## 調査結果と修正箇所

| 現状 | 修正する点 |
| --- | --- |
| 設定画面の全量取得はサイト別、個別カードだけ取得元順に処理 | 更新の入口を共通化する |
| Wisdom Guildの更新開始前にキャッシュを削除 | 前回価格保持を採用する場合は成功時だけ置換する |
| Wisdom Guildは別状態・状態不明も採用する | 対応表と代用方針を適用する |
| CardTraderは状態文字列の完全一致 | 公式API資料にはPlayedとHeavily Playedが別々に掲載されている。HPをPlayedに置換しない |
| Wisdom Guildの取得元状態はmatchedConditionに保存、表示はconditionを参照 | 所持状態と取得元状態を区別して表示する |
| カード情報補完の後に英語版価格補完とCardTrader取得を実行 | カード情報更新と価格更新を分離する |
| トークン保存直後に全量取得 | 手動更新を採用する場合は設定保存だけにする |
| Scryfall価格をCardTrader使用設定に連動して表示 | 価格用途の方針を明示し、取得元設定と一致させる |

## 検証するケース

- Wisdom Guild成功時にはCardTraderへ補完取得しない。
- Wisdom Guild不一致・通信失敗時、CardTrader未設定なら通信せず理由を表示する。
- 一部だけ失敗した全量更新でも成功分は保存される。
- 手動価格がある場合、外部価格の取得結果と表示上の優先順位を混同しない。
- 状態・言語・仕上げが異なるキャッシュを流用しない。
- 起動、オンライン復帰、トークン保存、カード登録から意図しない価格取得が起きない。
- 二重更新、オフライン、例外終了後も操作が正常に戻る。
- 既存バックアップ、所持カード、デッキの読み込みを維持する。

## 別段階で扱うもの

OCR削除、デッキ表示統合、並び替えメニュー、検索DB読み込みの改善は、価格機能の変更と分ける。

## 独立して進めた修正

- Wisdom Guildの価格詳細で、matchedCondition（取得元の状態）を表示する。不明は不明と表示し、所持状態で代用しない。
- 取得元のセットと言語を表示に利用する。古い保存形式では保存済みのセット・言語を利用する。
- API状態値の確認元：https://www.cardtrader.com/en/docs/api/full/reference
